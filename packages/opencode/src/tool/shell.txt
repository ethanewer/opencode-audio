Interactive shell. Keystrokes are sent to a single persistent tmux session that is shared across every call.

The terminal is stateful: working directory, environment, shell history, background jobs, and any open interactive program (editor, REPL, pager, prompt) survive between calls. The session is never reset unless `reset` is true.

Every call takes three fields: `analysis` (what you observe now), `plan` (what this batch will do), and `commands` (the keystrokes to send). The command array may be empty to poll for more output without sending input.

Each call returns the new output since the previous call, labeled `[New output]`. If nothing new was produced, the current visible terminal is returned instead, labeled `[No new output — showing current terminal]`.

# Sending commands
- Put shell command text in `keystrokes`; a trailing newline is auto-appended if you omit it.
- To send a control key, use `C-c` (Ctrl+C), `C-d`, `Escape`, `Tab`, `Up`, `Down`, `Enter`, `BSpace`, etc.
- To wait for a long command to finish, send `{ "commands": [], "duration": N }` to poll for N more seconds.
- Set `duration` per command: 0.1 for instant (cd, ls, echo), 1.0 for normal, larger for slow (builds, tests, installs). Never wait longer than 60 seconds; prefer to poll.
- Batch independent commands into one call when it saves round trips.

# File operations
There are no `read`, `write`, or `edit` tools — use the shell. All standard shell features are available: `>` and `>>` for redirection, `echo`, `printf`, `tee`, `cat > file <<EOF`, etc. Use whatever fits best. The two helpers below are just conveniences for common cases:
- **Read text files**: `cat path`, `sed -n 'START,ENDp' path`, `grep -n PATTERN path`, `head -N path`, `tail -N path`, `wc -l path`. Use `read_multimodal` only for PDFs, images, and audio files.
- **Append a single line**: `echo 'text' >> /abs/path` is fine. For multi-line content, `echo` gets painful to escape — use a heredoc instead.
- **Create or overwrite a file with multi-line content**: the bundled `write` helper ships stdin verbatim with no escaping, creates parent dirs, and reports the byte count. Equivalent to `cat > /abs/path <<'EOF' ... EOF` with a `mkdir -p` in front:
  ```
  write /abs/path <<'EOF'
  file content goes here, exactly as-is — no escaping needed
  EOF
  ```
- **Edit an existing file**: the bundled `patch` helper uses search/replace blocks — no line numbers, same semantics as a one-shot find-and-replace. Each block replaces an exact string with another exact string:
  ```
  patch /abs/path <<'EOF'
  <<<
  old exact text (must appear exactly once in the file)
  ===
  new text
  >>>
  EOF
  ```
  - The old text must match the file byte-for-byte, including indentation and trailing whitespace. Copy-paste from the file you just read.
  - If the old text isn't unique, include more surrounding lines until it is — or pass `--all` to replace every occurrence: `patch --all /abs/path <<'EOF' ...`.
  - Stack multiple `<<<...===...>>>` blocks in one call to make several edits at once. Each block is applied in order, to the file as modified by earlier blocks.
  - An empty old text (`<<<` immediately followed by `===`) prepends to the file (or creates it if it doesn't exist).
  - On mismatch or non-unique match, `patch` exits non-zero and does not modify the file.

# Before each call
Fill in `analysis` and `plan` honestly. They are visible to you on later turns and help you reason about progress. Keep them short (one or two sentences each). Do not repeat the command list in `plan`.
