Interactive shell. Keystrokes are sent to a single persistent tmux session that is shared across every call.

The terminal is stateful: working directory, environment, shell history, background jobs, and any open interactive program (editor, REPL, pager, prompt) survive between calls. The session is never reset unless `reset` is true.

Every call takes three fields: `analysis` (what you observe now), `plan` (what this batch will do), and `commands` (the keystrokes to send). The command array may be empty to poll for more output without sending input.

Each call returns the new output since the previous call, labeled `[New output]`. If nothing new was produced, the current visible terminal is returned instead, labeled `[No new output — showing current terminal]`.

# Sending commands
- Put shell command text in `keystrokes`; a trailing newline is auto-appended if you omit it.
- To send a control key, use `C-c` (Ctrl+C), `C-d`, `Escape`, `Tab`, `Up`, `Down`, `Enter`, `BSpace`, etc.
- To wait for a long command to finish, send `{ "commands": [], "duration": N }` to poll for N more seconds.
- Set `duration` per command: 0.1 for instant (cd, ls, echo), 1.0 for normal, larger for slow (builds, tests, installs). Never wait longer than 60 seconds; prefer to poll.
- Batch independent commands into one call when it saves round trips.

# File operations
There are no `read`, `write`, or `edit` tools — use ordinary bash. `read_multimodal` is only for PDFs, images, and audio files.

- **Read**: `cat path`, `sed -n 'START,ENDp' path`, `grep -n PATTERN path`, `head -N path`, `tail -N path`, `wc -l path`, `find DIR -name PAT`.
- **Single short line**: `echo 'text' >> /abs/path` to append, `echo 'text' > /abs/path` to overwrite.
- **Multi-line content (new file or full overwrite)**: use a quoted heredoc so nothing inside gets shell-expanded. Pick a delimiter that doesn't appear in the body (`EOF`, `PY`, `END`, etc.):
  ```
  mkdir -p /abs/dir
  cat > /abs/dir/file.py <<'EOF'
  file content goes here, exactly as written — no escaping needed
  EOF
  ```
  `cat >> path <<'EOF' ... EOF` appends the same way.
- **Targeted edit of an existing file**: the most reliable approach is to re-read the file, then rewrite the whole thing with `cat > path <<'EOF' ... EOF`. This is the shell equivalent of the old edit tool: no line numbers to get wrong, no search-and-replace ambiguity.
- **Small in-place tweak**: `sed -i 's/PATTERN/REPLACEMENT/' path` works, but beware — `sed -i` silently succeeds when PATTERN doesn't match, and regex metacharacters in PATTERN or REPLACEMENT need escaping. For anything non-trivial, prefer reading the file and rewriting it.
- **Large files where you want to patch rather than rewrite**: `patch(1)` accepts a unified diff on stdin if you produce correct `--- / +++ / @@` headers; otherwise, read-then-rewrite is safer.

# Before each call
Fill in `analysis` and `plan` honestly. They are visible to you on later turns and help you reason about progress. Keep them short (one or two sentences each). Do not repeat the command list in `plan`.
